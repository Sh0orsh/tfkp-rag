# Доказательный RAG по теории функций комплексного переменного

Система Retrieval-Augmented Generation (RAG) для ответов на тестовые вопросы по учебному корпусу **«Лекции по ТФКП» (Горяйнов, Половинкин, 2025)**. Система выбирает все правильные варианты ответа, формирует краткое обоснование и указывает исходные `block_id` использованных фрагментов. При недостаточности информации предусмотрен отказ от ответа (`abstain`).

## Автор

- **ФИО:** Шкарбан Степан
- **Группа:** М05-601б
- **Запуск:** локальный компьютер с NVIDIA GPU для генерации и CPU для поиска и эмбеддингов.

## Архитектура

```text
corpus.jsonl
    │
    ▼
build_index.py
    ├── разбиение текста на чанки (240 слов, перекрытие 40)
    ├── BM25 (построение при загрузке индекса)
    └── dense-эмбеддинги: intfloat/multilingual-e5-small
    │
    ▼
index/ (chunks.json, embeddings.npy)
    │
    ▼
predict.py + questions.jsonl
    ├── BM25 / dense / гибридный поиск (RRF)
    ├── удаление повторов по исходному block_id
    ├── выбор фрагментов для контекста
    └── локальная Qwen3.5-4B (4-bit, NVIDIA GPU)
    │
    ▼
answers.jsonl + trace.jsonl
```

Поиск и вычисление эмбеддингов выполняются на **CPU**. Генерация — **локально на GPU** с помощью `Qwen/Qwen3.5-4B`; внешний API и API-ключи не используются. Параметры индексации и генерации задаются в `config.json`.

## Локальная установка

Для генерации требуется **NVIDIA GPU с рабочими драйверами и CUDA-совместимой версией PyTorch**. В текущей реализации `local_llm.py` проверяет наличие CUDA и не поддерживает запуск генерации только на CPU. Точные требования к VRAM зависят от окружения; модель загружается в 4-битном формате через `bitsandbytes`.

1. Установите Python и Git, проверьте доступность GPU командой `nvidia-smi`.
2. Склонируйте репозиторий и перейдите в каталог проекта:

```bash
git clone https://github.com/Sh0orsh/tfkp-rag.git
cd tfkp-rag
```

3. Создайте виртуальное окружение и активируйте его:

```bash
python -m venv .venv
```

**Linux/macOS:**

```bash
source .venv/bin/activate
```

**Windows (PowerShell):**

```powershell
.venv\Scripts\Activate.ps1
```

4. Установите зависимости проекта:

```bash
python -m pip install -r requirements.txt
```

5. Поместите выданные `corpus.jsonl`, `dev_questions.jsonl` и `dev_gold.jsonl` в корневой каталог проекта. При первом запуске потребуется интернет для загрузки моделей из Hugging Face. В дальнейшем генерация выполняется локально, без API-ключей.

> В `requirements.txt` PyTorch не закреплён отдельной строкой: подходящую CUDA-сборку нужно установить самостоятельно. Для 4-битной загрузки необходима совместимая версия `bitsandbytes`.

## Запуск

**1. Построить индекс:**

```bash
python build_index.py --corpus ./corpus.jsonl --output ./index --config ./config.json
```

**2. Получить ответы и трассировку:**

```bash
python predict.py --index ./index --questions ./dev_questions.jsonl --output ./dev_answers.jsonl --trace ./dev_trace.jsonl --config ./config.json
```

**3. Запустить сравнение режимов:**

```bash
python run_experiments.py --index ./index --questions ./dev_questions.jsonl --gold ./dev_gold.jsonl --config ./config.json --output-dir ./experiments_output
```

**4. Пересчитать метрики из сохранённых результатов (без запуска LLM):**

```bash
python evaluate_existing.py --gold ./dev_gold.jsonl --results-dir ./experiments_output --output ./experiments_recomputed.csv
```

Скрипт экспериментов запускает пять отдельных прогонов модели и может выполняться продолжительное время. Команды выполняются из корня проекта в терминале с активированным виртуальным окружением.

## Экспериментальные режимы

| Режим | Описание |
|---|---|
| `no_context` | Генерация без фрагментов учебника |
| `baseline` | BM25 + один этап генерации |
| `final` | Гибрид BM25 + dense + RRF |
| `bm25_only` | Абляция без dense-поиска |
| `dense_only` | Абляция без BM25 |

Сохранённые результаты предыдущего локального запуска находятся в `dev_answers.jsonl`, `dev_trace.jsonl` и `experiments.csv`. Они не являются результатом повторного контрольного прогона после подготовки репозитория. Подробности и анализ ошибок — в [`report.md`](report.md).

## Форматы данных

**Входной корпус:** JSONL с полями `block_id`, `page`, `section`, `text`.

**Ответы:** одна JSON-запись на вопрос, включая `id`, `answer_ids`, `abstain`, `rationale`, `citations`. Ссылки указывают на исходные `block_id` корпуса (не на внутренние номера чанков).

**Трассировка:** одна запись на вопрос с `id`, `llm_calls`, `input_tokens`, `output_tokens`, `elapsed_ms`, `retrieved_block_ids`.

## Структура репозитория

- `build_index.py` — построение чанков и dense-индекса.
- `predict.py` — извлечение фрагментов, формирование промпта, ответы и трассировка.
- `local_llm.py` — локальная генерация Qwen.
- `run_experiments.py` — сравнительные прогоны.
- `evaluate_existing.py` — пересчёт метрик из сохранённых файлов.
- `config.json` — параметры системы.
- `requirements.txt` — зависимости.
- `report.md` — методика, результаты и ограничения.
- `dev_answers.jsonl`, `dev_trace.jsonl`, `experiments.csv` — результаты разработки.
- `own_questions.jsonl`, `own_gold.jsonl` — авторские тестовые вопросы и эталоны.

**Не публикуются:** корпус, PDF учебника, индекс, веса моделей, секреты и кэши.

## Известные ограничения и соответствие заданию

- В текущей версии генерация **только локальная**, без OpenAI-совместимого endpoint. Это сознательное решение для локального запуска, но **оно не соответствует требованию автоматической проверки**, в котором предусмотрены endpoint и заголовки `X-Question-ID` / `X-Submission-ID`.
- Параметры модели, sampling и лимиты запросов требуют сверки с официальным `runtime.json`.
- Для корректного вычисления метрики `Q` необходимы категории dev-вопросов; если они отсутствуют в эталонах, значение не следует восстанавливать предположительно.
- Источники в `own_gold.jsonl` требуют проверки по оригинальному `corpus.jsonl`.
- Полный контрольный запуск на отдельном локальном компьютере после подготовки этой версии репозитория не выполнялся.
